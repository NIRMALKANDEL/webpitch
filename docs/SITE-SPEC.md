# Website Pitch Platform — Full Site Specification (v2)

> Status: **specification only, no code written yet.**
> Repo: `webpitch` (Next.js 16.4, React 19.3, Tailwind v4 via `@tailwindcss/turbopack`, `cacheComponents` + `partialPrefetching` on).
> Who: **one independent developer** (not an agency), selling to small businesses in **India and English-speaking countries** (US, UK, Canada, Australia, New Zealand, Ireland, and others).
> Goal: a visitor picks their industry, opens a real working demo website, and contacts me to get one built.

**Changes from v1:**
- Personal brand, written in first person ("I"), with no agency language.
- WhatsApp number added.
- Country-based currency and pricing grounded in market research (§7).
- Web3Forms replaces Resend.
- Demos are set in a mix of Indian and international cities.
- Owner details filled in: Nirmal Kandel, nirmalatlance@gmail.com, illustrated avatar, not GST-registered.
- 3D, 4K video and modern effects added: Signature vs Essential demos (§6A), and a new `/whats-possible` page.

## 1. Tech decisions (keep it lean)

| Concern | Decision | Why |
|---|---|---|
| Framework | Keep the existing Next.js 16.4 App Router setup | Already scaffolded |
| Styling | Tailwind v4 through the **existing** turbopack loader (no PostCSS), tokens in `@theme` | Matches current `next.config.ts` |
| Animation | `motion` | Required by the brief |
| Icons | `lucide-react` | Required by the brief, no emoji icons |
| Fonts | `next/font/google`. Each demo loads its own fonts in its own layout | Fonts only download on the pages that use them |
| Images | Unsplash via `next/image` + `images.remotePatterns` (`images.unsplash.com`) | Free license, and the URLs live in data files |
| Forms | **Web3Forms**, submitted **from the browser** (§8) | Free tier, no server code. Its free plan doesn't allow server-side calls |
| Currency | Country detected from Vercel's `x-vercel-ip-country` header in `proxy.ts`, which sets a cookie. Prices are **hand-set per currency** (not FX-converted). A manual switcher is available | §7.3 |
| Validation | Hand-written `src/lib/validate.ts` (no zod) | Avoids a dependency for one form |
| Database / auth / CMS / payments | **None** in v1 | Not needed |
| Hosting | Vercel | Required by the brief |

| 3D | `three` + `@react-three/fiber` + `@react-three/drei`. They're **loaded only on pages that use 3D**, via dynamic import, client-only, mounted when in view | §6A. Verify R3F's React 19.3 compatibility before installing |
| Video | Self-hosted MP4/WebM in **Vercel Blob (public store)** with poster images. Several resolutions (2160p / 1080p / 720p) chosen by screen size | §6A.3 |
| Scroll effects | Motion's `useScroll` / `useTransform` (no GSAP, no Lenis) | Covered by the dependency we already add |

**New dependencies, total:** `motion`, `lucide-react`, `three`, `@react-three/fiber`, `@react-three/drei`. Nothing else.

> ⚠️ `AGENTS.md` warns that this Next.js version has breaking changes. **Before coding**, read the relevant guides in `node_modules/next/dist/docs/` for:
> - route groups and multiple layouts
> - `generateStaticParams` + `dynamicParams`, and `notFound()`
> - `useSearchParams` + Suspense under `cacheComponents`
> - **`proxy.ts`** (Next 16's replacement for `middleware.ts`): confirm the file name, how it reads request headers, and how it sets cookies
> - `next/font`, `next/image` `remotePatterns`, metadata, `sitemap.ts` / `robots.ts`
>
> Don't rely on memorised APIs.

| Skill | Use it for | Phase |

| **vercel:deploy / vercel:env** | Deployment and env vars | 6 |
| Design-md refs (`awesome-design-md/design-md/framer`, `/linear.app`) | Optional spacing and type-rhythm reference for the main site. Don't copy their branding | 2 |

**Anti-template rules. Every page must pass these:**
- No warm-cream background + serif + terracotta combination. No near-black background with an acid-green or vermilion accent.
- No "giant number + small label" stat hero. **There are no real stats or clients yet**, so we show none. Trust comes from the demos, the process, a real photo, and clear pricing.
- No ALL-CAPS eyebrow labels. No highlighting one word in a headline with colour or italic.
- Numbered markers only for real sequences (process steps, admission steps, the quality process).
- Motion: one orchestrated load moment per page, plus motion in response to user actions. **No** fade-up on every section.
- Copy is specific and first-person. Avoid "Elevate your business", "Unlock your potential" and "We are a passionate team".

## 4. Main site brand system

The skill suggested stone-black + gold, with Cormorant/Montserrat. Keep its neutrals, but swap the gold and the luxury serif, which would clash with the fashion and salon demos. The main site should feel like a **calm, precise frame** that lets the colourful demos stand out.

| Token | Value | Use |
|---|---|---|
| `--paper` | `#FAFAF9` | page background |
| `--ink` | `#0C0A09` | text, primary buttons |
| `--ink-2` | `#44403C` | secondary text |
| `--muted` | `#E7E5E4` | dividers, card borders |
| `--accent` | `#2F45E8` (cobalt) | links, focus ring, highlights |
| `--accent-soft` | `#E8EBFE` | tinted panels |
| `--whatsapp` | `#0F7A3F` | WhatsApp buttons (white text) |
| `--danger` | `#DC2626` | form errors |

- **Type:** `Bricolage Grotesque` (display) + `Geist` (body/UI, already in the repo). Scale: 14 / 16 / 18 / 22 / 28 / 40 / 56 / 76px. Body line-height 1.55, and line length about 72ch at most.
- **Shape:** radius 14px for cards and 999px for buttons. 1px borders. Use almost no shadow (one soft shadow on the hero browser frame).
- **Gradient:** one faint cobalt radial behind the hero frame only.
- **Light theme only** for the main site in v1.
- **Motion:** 150–250ms for UI and 400–600ms for the hero sequence. Wrap the app in `MotionConfig reducedMotion="user"`.

## 6. The 10 demo websites — individual specifications

### 6.0 Rules for every demo

1. **Own identity:** its own `layout.tsx`, `next/font` pair, colour tokens, layout structure and component shapes. **No** shared template with swapped colours. Only `DemoBar`, `Lightbox`, the `DemoForm` logic and `WhatsAppLink` are shared.
2. **Single page** with a sticky nav that scrolls to sections, an active-section highlight, and a mobile menu or bottom bar (chosen per demo).
3. **Clearly labelled as a demo:**
   - the DemoBar (6.11)
   - a footer line: "Concept website by {brandName} for a fictional business. Names, prices, reviews and photos are illustrative."
   - "Sample review" tags on all reviews
   - `robots: noindex` on every demo
4. **Honest demo forms:**
   - They validate fully.
   - On submit they show "This is a demo — nothing was sent. On your website, this enquiry would reach you like this:" with a formatted message preview, plus **Get a Website Like This** and **Chat on WhatsApp**.
   - WhatsApp order/cart flows send to **my** number, prefixed `[Demo order from {Brand} website]`.
5. **Fictional contact details never reach a real person.** Phone numbers are **display text only, never `tel:` links**. Use number ranges reserved for fiction where they exist:
   - UK `020 7946 0xxx`
   - US/Canada `555-01xx`
   - Australia `(03) 5550 xxxx`
   - India: plain display text

   Demo "Call Now" or "Email us" buttons open the honest demo panel or route to my WhatsApp. Fictional emails use `@example.com`.
6. Responsive at 375 / 768 / 1024 / 1440px, with no horizontal scroll and touch targets ≥44px.
7. `next/image` with `sizes`. Only the hero image gets `priority`. Meaningful alt text.
8. Prices inside a demo use **the demo city's currency** (the demo business's own prices), not the visitor's.

> Palettes start from the **ui-ux-pro-max** results ("Skill suggested"). They were adjusted so no two demos share a palette, a font pair or a layout concept. Every text/background pair is **verified in Phase 1** with a contrast checker.

#### 6A.2 3D rules (React Three Fiber)

- **Lazy-load:** each 3D scene is a client component loaded with `next/dynamic` (`ssr: false`). It mounts only when its container is near the viewport (IntersectionObserver), and its `<Canvas>` uses `frameloop="demand"` when idle.
- **Fallback first:** a poster image renders at the exact same size (no layout shift) and stays if:
  - WebGL is unavailable
  - `prefers-reduced-motion` is on
  - `navigator.connection.saveData` is on
  - the device has ≤4 GB memory (`deviceMemory`)
- **Budget:**
  - models ≤1.5 MB each (Draco/meshopt-compressed GLB) and textures ≤1K on mobile
  - `dpr={[1, 1.5]}` on mobile, `[1, 2]` on desktop
  - no post-processing on mobile
- **Controls:** drag to rotate, plus keyboard buttons (rotate left/right, reset, zoom) with labels. The canvas gets an `aria-label` describing what it shows. Page scroll is never hijacked: zoom works by pinch or buttons, not the scroll wheel.
- **Assets:** CC0 models and HDRIs from **Poly Haven**, or procedural geometry (tower, bolt, frame stack). If a Sketchfab CC-BY model is used, credit it in the demo footer. Store models in `public/models/` (small) or Vercel Blob.

#### 6A.3 Video rules ("live 4K" done responsibly)

- **Sources:** free-licence stock (Pexels, Mixkit, Coverr). Check each clip's licence page and record it in `docs/ASSETS.md`.
- **Encode** with ffmpeg into 3 renditions: **2160p** (desktops ≥1920px wide on fast connections), **1080p** (default desktop/tablet) and **720p** (mobile). Each comes as WebM (VP9/AV1) + MP4 (H.264) fallback, 8–15s seamless loops, **no audio track** for background clips, and a target of ≤6 MB for the 4K file and ≤1.5 MB for 720p.
- **Hosting:** Vercel Blob public store (upload once via the dashboard or CLI). URLs live in each demo's data file. Runtime needs no token.
- **`<BackgroundVideo>` component (shared):**
  - picks the rendition by viewport width and `connection.effectiveType`
  - `muted autoplay loop playsInline preload="none"` + a `poster` (AVIF/WebP)
  - starts when visible and pauses when off-screen or the tab is hidden
  - shows a visible **pause/play button** (accessibility requirement for motion longer than 5s)
  - shows the poster only under reduced motion or Save-Data
- Text over video always sits on a gradient scrim so contrast stays ≥4.5:1.
- Showreels with sound (photography) start muted, with a clear "Play with sound" button.

**Every price on the site is read from this file. No exchange-rate maths at runtime.**

### 7.3 Currency detection (`src/proxy.ts` + `CurrencyProvider`)

1. `proxy.ts` runs on the main site routes (not demo assets). If there's no `cur` cookie, it reads the `x-vercel-ip-country` request header and maps it:
   - IN → INR, US → USD, GB → GBP, IE → EUR
   - AU → AUD, CA → CAD, NZ → NZD
   - **any other country → USD**

   It then sets `cur=<code>` (1 year, `SameSite=Lax`).
2. Pages stay **static**: the HTML is identical for everyone, and prices are rendered by a small client `<Price id="starter" />`.
   - On first render it shows a fixed-width placeholder (no layout shift), then fills in the price from the cookie.
   - If there's no cookie (local dev), it falls back to the timezone: `Asia/Kolkata` → INR, `Europe/London` → GBP, `Australia/*` → AUD, `Pacific/Auckland` → NZD, `America/Toronto|Vancouver|…` → CAD, other `America/*` → USD, else USD.
3. A **currency switcher** (footer + pricing page) overwrites the cookie and updates prices instantly through context.
4. Formatting uses `Intl.NumberFormat` with the right locale (`en-IN` → ₹4,999; `en-GB` → £249; and so on), with no decimals.
5. The contact form sends the selected `currency` and `country` with the enquiry, so I know which price list they saw.

### 7.4 Things you need to decide (fine print in `pricing.ts`)

- **Payment methods.** India: UPI / bank transfer. International: **to be decided later**. Until then, the site says "International payment options shared with your quote" (no specific provider named).
- **Payment terms.** Proposed: 50% upfront, 50% before launch.
- **Tax wording.** **Not GST-registered**, so prices are shown as final, with **no "+ GST" line**. If you register later, add `taxNote` in `pricing.ts`.
- **Domain & hosting.** Proposed: billed at cost, with the client as owner.

## 8. Lead generation — Web3Forms & WhatsApp

### 8.1 Web3Forms facts (checked Oct 2026)

- Free plan: **250 submissions/month**, unlimited forms and domains, spam protection, hCaptcha available, and submissions kept for about 30 days. Webhooks, file uploads, autoresponders and Turnstile/reCAPTCHA are paid ([pricing](https://web3forms.com/pricing)).
- **Free plan = browser-side submission only.** "Server side usage requires paid plan + server IP whitelisting" ([API reference](https://docs.web3forms.com/getting-started/api-reference)). So the form posts **directly from the browser**, with no Server Action.
- The access key only identifies which inbox gets the email, so it's designed to sit in client code. Store it as `NEXT_PUBLIC_WEB3FORMS_KEY`.
- Responses:
  - `200 {success: true, …}`
  - `400 {success: false, message}`
  - `429` rate limit
  - `500` server error
- Supported special fields: `access_key`, `subject`, `replyto`, `botcheck` (honeypot), `redirect` (not used).

### 8.2 Submission flow (real, never fake success)

1. `EnquiryForm` (client) validates with `lib/validate.ts`. Errors appear inline, linked by `aria-describedby`, plus an `aria-live` summary.
2. **Spam:**
   - a hidden `botcheck` checkbox, which must stay unchecked
   - a minimum fill time (reject if under 3s)
   - length limits on all fields
   - if spam becomes a problem, enable hCaptcha (free on Web3Forms; it would add one small dependency)
3. `fetch('https://api.web3forms.com/submit', { method: 'POST', headers: { 'Content-Type': 'application/json', Accept: 'application/json' }, body })`. Verify JSON support in the docs, and fall back to `FormData` if needed. The body contains:
   - `access_key`
   - `subject: "New enquiry — {category} — {websiteType} — {name} ({country})"`
   - `from_name: "{brandName} website"`
   - `replyto: email`
   - all fields + demo, package, currency, page URL and a timestamp
4. **Success** only when the parsed JSON has `success === true`. Show "Thanks {name} — I'll reply within 12 hours on WhatsApp or email." plus a summary and **Also send on WhatsApp**.
5. **Any other result** (non-2xx, `success: false`, 429, network error or timeout after 15s): show the error message, keep all values, and offer **Send via WhatsApp instead** with the full enquiry text.
6. **Key missing** (`NEXT_PUBLIC_WEB3FORMS_KEY` empty): the form shows a notice, "The form isn't available right now — message me on WhatsApp", and the submit button becomes a WhatsApp button. Never a fake success.

**Environment variables (`.env.example` + README):**

| Var | Required | Example | Purpose |
|---|---|---|---|
| `NEXT_PUBLIC_WEB3FORMS_KEY` | yes | `xxxxxxxx-xxxx-…` | From web3forms.com: enter your email and the key arrives by email. Enquiries go to that email |
| `NEXT_PUBLIC_SITE_URL` | yes | `https://yourdomain.com` | Canonical URLs, sitemap, OG |

**Setup:**

2. Add it to `.env.local` for development.

4. Redeploy. `NEXT_PUBLIC_` vars are baked in at build time.

## 9. Shared UX, accessibility, performance & SEO standards

- **Accessibility:**
  - Landmarks, one H1 per page, skip link, visible focus rings everywhere.
  - Labels above inputs (not placeholder-only). Errors next to the field + an `aria-live` summary.
  - Icon buttons get an `aria-label`. Contrast ≥4.5:1, **verified for every pair in Phase 1**.
  - Modals, drawers and the lightbox trap and restore focus and close on Esc. Carousels and slideshows can be paused.
- **Motion:** `MotionConfig reducedMotion="user"`. Animate transform and opacity only, except the accordion height.
- **Performance:**
  - Server Components by default, with small client islands.
  - `next/image` with `sizes`. `next/font` with `display: swap` and Latin subsets.
  - Pages stay static (the currency is client-side), so they're fast from Vercel's CDN worldwide.
  - Target LCP < 2.5s and CLS < 0.1 on mobile.
- **SEO:**
  - Metadata per page, `sitemap.ts`, `robots.ts`. **Demos are `noindex`.**
  - `ProfessionalService` JSON-LD with `areaServed`: India, US, UK, CA, AU, NZ, IE.
  - `en` language. `hreflang` isn't needed, since there's one English site.
- **Analytics (later):** Vercel Web Analytics is a one-line addition.
